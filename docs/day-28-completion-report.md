# Day 28 Completion Report

**Date:** August 17, 2026
**Status:** Complete for the live lifecycle and UI-observation milestone.

## Completed

- Added a versioned Test Job status contract with seven deterministically
  ordered pipeline stages.
- Added queued, leased, acknowledged, running, completed, failed, rejected, and
  expired job states.
- Added identity-bound acknowledgement, stage update, and completion methods.
- Added strict lifecycle ordering and idempotent acknowledgement/completion.
- Prevented downstream PASS after an upstream failure while preserving cleanup.
- Added stable, allowlisted detail codes instead of accepting Runner text.
- Added latency limits and immutable terminal stage results.
- Added a session-bound read-only job-status endpoint.
- Connected the interface to bounded one-second polling for at most 150
  attempts.
- Added explicit PENDING and IN PROGRESS UI states.
- Added non-terminal copy for delayed endpoint, SIEM ingestion, and alert
  observations.
- Simplified failure and root-cause language and hid irrelevant field evidence
  during other states.
- Reworked the internal five-minute demo narrative around live evidence and the
  current transport boundary.

## Deliberately deferred

The lifecycle mutation methods are not exposed as unauthenticated HTTP routes.
The next technical milestone connects the Windows Runner through an
authenticated outbound transport, verifies the signed job locally, and then
drives these stage updates with real evidence. Until that connection exists,
the browser will show QUEUED and eventually EXPIRED rather than simulated PASS.

External demos and customer outreach remain deferred under ADR-0002.
